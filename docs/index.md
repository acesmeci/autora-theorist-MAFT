# Search Algorithm: a description of the search algorithm, and how the goodness of the equation was determined? 

Our theorist (`ChunkedPolynomialRegressorSparse`) is a **piecewise sparse symbolic regression model**.

The algorithm proceeds as follows:

1. **Clustering **  
   - If `k > 0`, input space is divided into regions using KMeans (up to `max_chunks`).
   - Each region gets its own sparse local model.

2. **Feature construction**  
   - Generates polynomial, interaction, logarithmic, and power-based features via `FeatureLibrary`.
   - Degree ∈ {1, 2}, powers ∈ {0.5, 1.5}, logs shifted to ensure numerical stability.

3. **Sparse model fitting**  
   - Within each region, features are standardized and fed to **Orthogonal Matching Pursuit (OMP)** to select a small subset of informative features (sparse representation).
   - A final **Ordinary Least Squares (OLS)** regression refits the selected features for accurate coefficients.

4. **Model selection**  
   - Searches over all (degree, k) configurations.
   - Chooses the one minimizing:  
     **score = MSE + λ × complexity_penalty**,  
     where complexity is the number of symbols used (≤ 40).

Thus, the algorithm balances **accuracy** and **interpretability** using a symbolic budget constraint.


# Search Space: which search space was used and how was the search otherwise constrained?
The search space is composed of symbolic features generated by the `FeatureLibrary`:

- Linear terms: `x_i`
- Quadratic terms: `x_i^2`
- Interactions: `x_i * x_j`
- Logarithmic: `ln(x_i + shift_i)`
- Power-law: `(x_i + shift_i)^c


# Constraints:
- Maximum polynomial degree: 2
- Maximum chunks (regions): 4
- Global symbol budget: ≤ 40 symbols (includes coefficients and intercepts)
- Sparse feature cap per region determined by available budget

These constraints ensure that the resulting equations remain interpretable and not overfit.
